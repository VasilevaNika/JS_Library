# Журнал решений и отклонений

## Шаг 1. Анализ макетов

- **Превью в PDF, а не в PNG.** В `design/previews/` лежат PDF (7 файлов, 76 страниц), а CLAUDE.md называет эталоном PNG. Для сверки используем PDF.
- **HTML покрывает не всё.** `design/screens/` содержит один упакованный бандл с 12 артбордами только раздела «Поиск»: Главная (7 состояний), Результаты (2), Не найдено (2), Меню. Экраны книги, брони, входа, профиля и все модераторские есть только в PDF. Для них точные значения берём из дизайн-системы (`design/system/`), а тексты — из PDF.
- **Варианты в HTML.** В HTML есть варианты, которых нет на отдельных артбордах: Результаты `offline` и `live`. Эти же варианты есть в P:Состояния:1,4 — расхождения нет.
- **Платформа модератора.** По дизайн-системе: «Мобильный веб для студентов и десктоп для модератора». Это не совпадает с задачей «приложение для iOS и Android» — вынесено в spec.md, Q1.

## Шаг 2. Проверка spec.md человеком

- Добавлены HTML для всех разделов (`design/screens/*.html`). Тексты и состояния сверены — с PDF расхождений по текстам нет.
- Модераторские макеты в HTML — 1440×900 (в PDF они уменьшены до 1080×675). Источник размеров — HTML.
- В HTML уведомлений есть строка, которой не видно в PDF: «Книги «Механика» нет на полке. Свяжитесь с библиотекой» (17 сент., 11:00).
- Решения по Q1–Q11 — в spec.md §5. Коротко: модератор — раскладка «как на ноутбуке»; уведомления не отправляются; аккаунты локальные; зависимости `expo-camera`, `expo-document-picker`, SheetJS, `expo-sharing`, `expo-crypto`; недостающие состояния собираем из компонентов дизайн-системы; офлайн и «гонка» — через dev-переключатель; пункты без экранов неактивны; плейсхолдеры «[…]» заменяем тестовыми значениями; гостю — урезанное меню с кнопкой входа; дата реальная.
