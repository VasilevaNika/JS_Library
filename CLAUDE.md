# Проект

Учебное мобильное приложение для iOS и Android. Дизайн полностью готов в `design/`.
Задача — перенести его в код один в один, без собственных дизайнерских решений.

# Стек

- Expo SDK (последняя стабильная), React Native, TypeScript в режиме strict
- Навигация: expo-router (файловая маршрутизация в `app/`)
- База данных: expo-sqlite, локально на устройстве
- Без UI-китов (NativeBase, Paper, Tamagui и т.п.) — все компоненты свои
- Новые зависимости ставить только через `npx expo install`, чтобы версии совпадали с SDK
- Приложение должно запускаться в Expo Go — не использовать библиотеки, требующие нативной сборки

# Структура

```
app/                 экраны и навигация (expo-router)
src/components/      переиспользуемые компоненты из дизайн-системы
src/theme/tokens.ts  все дизайн-токены
src/db/              схема, миграции, функции доступа к данным
src/mocks/           тестовые данные для первого запуска
docs/spec.md         спецификация: экраны, навигация, состояния, сущности
docs/decisions.md    журнал решений и отклонений от макета
PLAN.md              план работ с чекбоксами
```

# Дизайн

- `design/system/` — источник токенов и компонентов. Значения брать оттуда.
- `design/screens/*.html` — источник точных значений и текстов интерфейса.
  Структуру DOM НЕ копировать: экспорт содержит абсолютное позиционирование и лишние обёртки.
  Верстать заново на flex, собирая экраны из компонентов `src/components/`.
- `design/previews/*.png` — эталон для визуальной сверки.
- Если HTML и PNG расходятся — приоритет у HTML, расхождение записать в `docs/decisions.md`.

# Правила кода

- Цвета, шрифты, отступы, радиусы, тени — только из `src/theme/tokens.ts`. Хардкод значений запрещён.
- Перед созданием компонента проверить, нет ли подходящего в `src/components/`. Не дублировать.
- Экраны не обращаются к SQLite напрямую — только через функции из `src/db/`.
- Каждый экран реализует все свои состояния из `docs/spec.md` (загрузка, пусто, ошибка, норма).
- Тексты интерфейса — точно как в макете, на русском.
- Никаких `any` без комментария, почему иначе нельзя.

# Порядок работы

Работа ведётся строго по `PLAN.md`. Протокол для каждого шага:

1. Взять первый невыполненный шаг из `PLAN.md`.
2. Выполнить его полностью, в рамках только этого шага.
3. Проверить: `npx tsc --noEmit` и `npx expo lint` без ошибок.
   Если ошибки — исправить, максимум 3 попытки. Не получилось — остановиться и описать проблему.
4. Отметить шаг `[x]` в `PLAN.md`, добавить под ним 1–3 строки: что сделано, что отклонено от макета.
5. Сделать коммит: `git add -A && git commit -m "step N: <название>"`.
6. Перейти к следующему шагу без ожидания подтверждения.

Остановиться и ждать человека, если:
- шаг помечен `⏸ СТОП`;
- в дизайне неоднозначность, которую нельзя решить по HTML и PNG;
- нужна зависимость, не работающая в Expo Go;
- проверки не проходят после 3 попыток.

При остановке — коротко: где остановился, почему, какое решение нужно.
