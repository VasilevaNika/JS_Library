Задача: сделать для приложения «Библиотека кампуса» свой MCP-сервер, через который ИИ-ассистент (Claude Desktop) сможет выполнять те же действия, что пользователь делает через формы приложения. И написать к нему объяснение для преподавателя простым языком.

Работай по правилам из CLAUDE.md. Сначала изучи проект, потом действуй по шагам ниже. После каждого шага — коммит.

## Шаг 1. Принцип

MCP-сервер НЕ кликает по формам в браузере. Каждая форма = один инструмент (tool), который вызывает ту же функцию, что и кнопка «Отправить» в форме, с той же валидацией и теми же текстами ошибок. Логику не дублировать: если её нет в отдельном модуле — сначала вынеси её туда из экранов, потом используй и в приложении, и в MCP.

## Шаг 2. Сервер

- Папка mcp-server/, TypeScript strict, официальный SDK `@modelcontextprotocol/sdk`, схемы параметров через `zod`, транспорт stdio.
- В stdio-сервере ничего не писать в stdout (это ломает протокол) — логи только через console.error.
- Инструменты (названия и набор уточни по шагу 0):
  - читающие: search_books, get_book, list_my_bookings, get_booking_by_code, list_journal (для модератора);
  - меняющие: create_booking, cancel_booking, join_queue, leave_queue, update_profile, add_book, update_book, issue_book, return_book.
- У каждого инструмента: понятное описание на русском (его читает нейросеть, чтобы понять, когда инструмент вызывать), описание каждого параметра, пример в описании.
- Роли: сервер работает от имени пользователя из переменных окружения (LIBRARY_USER_EMAIL, LIBRARY_ROLE=student|moderator). Инструменты модератора недоступны студенту — возвращать понятную ошибку.
- Опасные действия (cancel_booking, issue_book, return_book, update_book) требуют параметр confirm: true. Без него — вернуть, что именно будет сделано, и ничего не менять.
- Ошибки возвращать текстом для человека, а не стектрейсом: «Лимит броней: у вас уже 3 активные брони».
- Каждое меняющее действие писать в лог-таблицу mcp_audit (время, инструмент, параметры, результат).

## Шаг 3. Проверка

- Юнит-тесты на каждый инструмент: успешный сценарий + минимум одна ошибка (нет прав, лимит, неверные данные, нет confirm).
- Скрипт `npm run inspect`, запускающий сервер в MCP Inspector (`npx @modelcontextprotocol/inspector`), чтобы вызывать инструменты руками.
- Готовый блок для claude_desktop_config.json (Windows, Claude из Microsoft Store: файл лежит в %LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\).
- Демо-сценарий из 5 фраз, которые я скажу Claude Desktop на защите, с ожидаемым результатом каждой. Прогони их сам через Inspector и убедись, что они работают.

## Шаг 4. Документ для преподавателя — docs/MCP.md

Пиши для человека, который не программист. Никакого жаргона без объяснения, каждое понятие — с бытовой аналогией. Структура:

1. **Что это за проект в двух абзацах.** Что умеет приложение и зачем к нему MCP.
2. **Что такое MCP.** Аналогия (например, переводчик или официант между нейросетью и приложением). Чем MCP отличается от «нейросеть сама ходит по сайту».
3. **Схема.** Mermaid-диаграмма: Пользователь → Claude Desktop → MCP-сервер → функции приложения → база данных. Под схемой — что происходит на каждой стрелке.
4. **Путь одного запроса по шагам.** На примере «Забронируй мне „Грокаем алгоритмы“»: какой инструмент выбрала нейросеть и почему, какие параметры передала, что проверил сервер, что записалось в базу, что увидел пользователь.
5. **Таблица инструментов.** Инструмент | какую форму приложения заменяет | что делает | кто может вызывать | пример фразы пользователя.
6. **Безопасность.** Роли, подтверждение опасных действий, журнал действий, почему нейросеть не может сделать то, чего не может сам пользователь.
7. **Как запустить и проверить.** Пошагово, с командами, для Windows. Отдельно: проверка через Inspector и подключение к Claude Desktop.
8. **Демо для защиты.** Сценарий из шага 3.
9. **Ограничения и что можно улучшить.**
10. **Вопросы, которые может задать преподаватель, и ответы на них.** 10–12 штук, например: «Чем MCP отличается от обычного API?», «Что будет, если нейросеть передаст неправильные данные?», «Почему stdio, а не HTTP?», «Как сервер понимает, кто пользователь?».
11. **Словарик терминов.** MCP, сервер, клиент, инструмент (tool), параметр, схема, stdio, JSON, API, валидация.

В конце перечитай docs/MCP.md глазами человека без технического образования и перепиши все места, где без знания программирования непонятно.
